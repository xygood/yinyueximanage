# 教学日历「从 Word 模板导入」方案总结

## 一、当前问题

1. **教学内容未按排课时间重排**  
   导入后，Word 里的行与日历行按「行下标」一一对应；日历行包含「有排课的周」和「放假的空周」。若 Word 是连续 16 行而日历中间有空周，就会错位，且没有按「实际有课的周次」重新分配。

2. **备注列覆盖禁排原因**  
   导入时对**所有**日历行（含空周）都写入了 Word 的「备注」；空周原本展示的是禁排原因（如「清明节放假」），被 Word 里的备注覆盖。

3. **同模板给其他班级用时只带了教学内容**  
   年级模板只存了 `content_items`（教学内容），没有存备注列；其他班级/小组加载模板时只填了教学内容，备注列没有从模板加载，且未保留该班级日历已有的禁排原因。

---

## 二、目标行为（约定）

- 从 Word 中**只按「共 16 次」**解读：不关心 Word 表里一共多少行、中间是否空行，只要按顺序得到 16 条「教学内容」和 16 条「备注」即可（不足 16 条则按实际条数分配）。
- 分配时**只针对「有排课」的日历行**：按当前日历中有排课的行顺序，依次填入第 1～N 条教学内容和第 1～N 条备注；**空周（放假的周次）不参与分配**，既不写教学内容，也不用 Word/模板的备注覆盖，**保留原日历中的禁排原因**。
- 其他班级使用同一模板时：**教学内容和备注都从模板加载**，分配规则同上（只填有排课的行）；备注列若该行已有禁排原因则**保留禁排原因**，不覆盖。

---

## 三、方案要点

### 3.1 Word 导入时的分配逻辑

| 步骤 | 说明 |
|------|------|
| 1. 解析 Word | 从表体按行顺序读取「教学内容」「备注」两列，得到两个列表 `content_list`、`remark_list`。若需严格 16 条：按行顺序取前 16 行（空行也算一行），或按「前 16 条非空教学内容」收集，二者择一并在产品上统一；不足 16 条则长度为 N。 |
| 2. 确定「有排课」行 | 以当前 header 调用 `_build_calendar_entries` 得到 `rows`。从中**只取有排课的行**：`schedule_id` 非空且 `is_empty_week == False`，并按 `week_number`（及同一周内顺序）排序，得到 `teaching_rows`，数量记为 M。 |
| 3. 分配教学内容 | 对 `teaching_rows[i]`（i=0..M-1），设置 `teaching_content = content_list[i]`（若 i ≥ len(content_list) 则用空字符串或保留原值）。 |
| 4. 分配备注（保留禁排） | 对 `teaching_rows[i]`，若该行**当前已有备注**（如从禁排原因来的），则**不覆盖**；仅当该行备注为空时，才设置 `remark = remark_list[i]`。 |
| 5. 空周 | 所有 `is_empty_week == True` 的行：不写入导入的教学内容，也不写入导入的备注，保持原有 `remark`（禁排原因）不变。 |

这样：教学内容按「实际排课的周次顺序」重排并跳过放假周；备注列不会覆盖禁排原因。

### 3.2 年级模板：同时存「教学内容」和「备注」

| 项目 | 说明 |
|------|------|
| 存储 | 导入时若选择了班级，除现有 `content_items` 外，增加 `remark_items`（或沿用现有表结构扩展字段），保存本次导入的 16 条备注（与 16 条教学内容一一对应）。 |
| 加载 | 同年级其他班级/小组加载模板时：拉取 `content_items` 和 `remark_items`；只对**该班级/小组当前日历中的「有排课」行**按顺序填充；备注列同样采用「已有禁排原因则保留，否则用模板备注」的规则。 |

这样：其他班级用相同模板时，教学内容和备注都会按 16 次重新分配，且不覆盖禁排原因。

### 3.3 与现有逻辑的衔接

- **空周的识别**：以 `rows` 中 `is_empty_week === true` 且 `schedule_id` 为空为准；这些行不参与「16 条」的分配。
- **有排课行的顺序**：与 `_build_calendar_entries` 返回的 `rows` 中「非空周」部分的顺序一致（按周次、同周内按日期/节次），保证与前端展示顺序一致。
- **年级模板的 16 条**：保存时按「有排课行」顺序从本次导入结果抽取 16 条（或 M 条）教学内容与备注；加载时仍按「目标班级的有排课行」顺序填回，实现「按 16 行重新分配并跳过空周」。

---

## 四、实现要点汇总

1. **导入接口**（如 `import_teaching_calendar`）  
   - 解析 Word 得到 `content_list`、`remark_list`（长度最多 16，或按约定取前 16 行）。  
   - 从 `_build_calendar_entries` 的 `rows` 中筛出 `teaching_rows`（仅 `schedule_id` 非空且非空周）。  
   - 仅对 `teaching_rows` 按下标写入 `teaching_content` 和（在无现有备注时）`remark`；空周行不写入。  
   - 若保存年级模板：同时写入 `content_items` 与 `remark_items`（需模型/API 支持 `remark_items`）。

2. **年级模板模型/API**  
   - 若 `GradeTeachingContent` 当前仅有 `content_items`，则增加 `remark_items`（JSON 数组，长度与 `content_items` 一致）；导入时写入，GET 年级模板时返回。  
   - 加载模板到某班级日历时：只对有排课行分配 `content_items[i]` 与 `remark_items[i]`，且备注遵循「有禁排则保留」规则。

3. **前端**  
   - 无需改交互；导入仍上传 Word，成功提示可说明「已按实际排课周次重排，空周已跳过，禁排原因已保留」。  
   - 其他班级使用模板时，若当前由前端请求「年级模板」再写回日历，需确保请求/写入包含备注列，并按上述规则保留禁排原因（可由后端统一实现「加载模板」接口，前端只调一次即可）。

---

## 五、小结

| 需求 | 方案 |
|------|------|
| 教学内容按排课时间重排、跳过放假周 | Word 解析出 16 条内容，只往「有排课」行按顺序填；空周不填。 |
| 备注不覆盖禁排原因 | 仅对「有排课」行写备注；若该行已有备注（禁排原因）则保留不覆盖。 |
| 其他班级用同一模板时也要备注、且保留禁排 | 年级模板增加 `remark_items`；加载时教学内容和备注都按有排课行分配，备注列沿用「有禁排则保留」规则。 |

按上述实现后，可满足：**导入的 Word 无论 16 次如何排列（总行数、中间空行），都按 16 条重新分配；分配时自动跳过空周；备注列保留原日历的禁排原因；其它班级用相同模板时教学内容和备注都会加载，并同样保留禁排原因。**

## 六、数据库（已有库需执行）

若表 `grade_teaching_contents` 已存在，需新增列 `remark_items`（JSON 类型，可为空），例如：

- **SQLite**: `ALTER TABLE grade_teaching_contents ADD COLUMN remark_items JSON DEFAULT '[]';`
- **MySQL**: `ALTER TABLE grade_teaching_contents ADD COLUMN remark_items JSON DEFAULT NULL COMMENT '备注列表，与 content_items 同序';`

新建库由 SQLAlchemy 建表时已包含该字段，无需额外操作。
