## 教学日历功能设计说明

### 1. 功能概述

- **目标**：为每位教师的每门课程（含合班、分组小组课）生成符合学校模板的教学日历，支持在线编辑与导出 Word 文档。
- **入口**：后台侧边栏增加独立菜单 `教学日历`，对应独立页面（例如 `/teaching-calendar`），不依赖 `/arrange-class` 页面。
- **模板结构**：仿 Word 三页：
  - 第一页：课程与教师信息页。
  - 第二页：按周次与每节课生成的教学日历表（有“教学内容”列）。
  - 第三页：审核签字页（固定格式）。
- **版式要求**：导出的 Word 文件以现有的《多声部音乐分析与写作2》教学日历.docx 为**唯一基准模板**，包括页边距、字体字号、行距、表格线样式、列宽、分页位置等版式均保持一致，仅替换其中的文字内容（课程信息、表格行内容等），不改变版式结构。

本设计文档用于约定逻辑规则，作为后续实现与调整时的参考。

---

### 2. 日历对象粒度与适用范围

#### 2.1 粒度定义

一份教学日历对应以下维度的一组唯一组合：

- **学期**：`semester_id`
- **教师**：`teacher_id`
- **课程**：`course_id`
- **教学班/行政班**：`teaching_class_id`（或班级 id）
- **小组（可选）**：`group_id`（仅小组课时使用）

> 约定：`(semester_id, teacher_id, course_id, teaching_class_id, group_id)` 唯一确定一份教学日历。

#### 2.2 多课程 / 合班 / 小组课规则

- **一名教师多门课程**：  
  - 每门课程单独一份教学日历（按上面的唯一组合生成多份）。

- **多班级合上同一课程（合班）**：  
  - 按“教学班”出一份日历（即多个行政班合并后的教学班为一个对象）。  
  - **展示上**：第一页信息页中的“授课专业班级”字段显示**实际参与的各个行政班级名称列表**，而不是仅显示教学班编号。

- **一个班拆为多个小组的小组课**：  
  - 每个小组视为一个独立教学对象：`课程 + 教学班 + 小组`。  
  - 每个小组单独导出一份教学日历。  
  - 第一页信息页中展示方式：
    - 仍然只使用“授课专业班级”这一字段，不新增单独字段。
    - 对于小组课，在“授课专业班级”字段内换行追加小组学生姓名列表（例如：第一行显示班级名称，第二行显示“小组学生：A, B, C, …”），并在 Word 模板中将学生姓名这一行的字号适当调小，以便在有限空间内容纳更多姓名。

### 3. 数据来源与依赖

教学日历依赖以下数据源：

- **学期与周次配置**：
  - 用于确定本学期有效周次范围，以及每周对应的日期区间。

- **排课结果（课表）**：
  - 每条记录代表一次具体上课，包含：`schedule_id / week / date / weekday / time_slot / duration_hours / teacher_id / course_id / teaching_class_id / group_id(可选)` 等。

- **节假日 / 禁排配置**：
  - 用于识别因节假日产生的“无课周”或特殊禁排情况。
  - 备注列只需反映**节假日相关的禁排原因**，不做补课说明。

### 4. 页面结构与展示逻辑（仿 Word）

#### 4.1 第一页：信息页

- 主要字段（可依据实际字段名略有调整）：
  - 学校名称（如“武昌理工学院”，可固定）
  - 标题：`教学日历`
  - 学年学期文本（例如：`2025 — 2026 学年第 2 学期`）
  - 课程名称
  - 学院
  - 系（部）
  - 授课专业班级（对合班情况可展示多个班级名称）
  - 主讲教师
  - 职称
  - 选用教材
  - 总学时（含理论学时、实践学时）
  - （小组课时）小组学生姓名列表
- **数据来源**：
  - 初始化时自动从课程、班级、教师信息中推断并填入默认值；
  - 页面上以表单形式呈现，允许教师/管理员在前端修改，修改结果会保存到数据库。

#### 4.2 第二页：教学日历页（核心表格）

- **表头固定**：
  - `周次 / 授课日期 / 节次 / 学时 / 教学内容 / 备注`

- **行粒度：一节课一行**：
  - 每条排课记录（一节具体的课）生成一行。
  - 字段含义：
    - **周次**：从排课记录中的 `week` 字段转换而来（展示时可用中文数字：一、二、三……）。
    - **授课日期**：该次上课的具体日期（例如 `3 月 2 日`）。
    - **节次**：该次上课的节次范围（例如 `3-4 节`）。
    - **学时**：该次上课对应的学时数。
    - **教学内容**：本次课的教学主题或内容，由教师手动填写，可编辑。
    - **备注**：用于说明节假日相关禁排或其他必要信息，可编辑。

- **多次课周的规则**：
  - 若某一周有多次课，则该周会生成多行，**每行的“周次”列单独填写，不做单元格合并**。

- **未排课周的显示（空周）**：
  - 以学期周次配置为基准，遍历所有学期内的周次。
  - 对于**在学期范围内、但当前课程本班级本小组没有排课的周次**：
    - 仍然生成 **一行空行**，用于提醒教师“该周不上课”，并方便填写如“机动周”等说明。
    - `周次` 列填写该周次，其余列默认空。
  - **完全没有排课记录时**（本课程本班级本小组在该学期未排任何课）：
    - 仍然根据学期周次配置生成整学期的空表，每个周次一行，便于教师下载“空表”后手工填写或作为线下模板使用。

- **节假日与禁排的备注规则**：
  - 若某周因节假日或禁排规则导致**整周不上课**：
    - 该周的空行 `备注` 列中自动填写相应**节假日禁排原因**的简要描述（例如“清明节放假”“国庆节放假”）。
  - 对于有排课的周，若某次课被禁排数据标记为节假日相关调整，可在该行 `备注` 中自动注入简要说明。  
  - **不需要**对补课做额外说明：补课视为正常排课记录，按普通行展示即可，备注列只关注节假日禁排。

#### 4.3 第三页：审核页

- 固定格式的审核签字区域，例如：
  - 教师签字
  - 教研室主任签字
  - 系主任签字
  - 教务处审核
  - 日期
- 此页内容主要为静态模板，少量可编辑文本即可（如审核意见）。
  - **日期默认值约定**：
    - 春季学期：第三页中的日期位置默认仅体现 **2 月**（例如 `2025 年 2 月`），不预填具体日。
    - 秋季学期：第三页中的日期位置默认仅体现 **8 月**（例如 `2025 年 8 月`），不预填具体日。
    - 如需具体日数，由教师/教务在打印前于 Word 中手写或补充。

### 5. 可编辑性与交互约定

- **可编辑内容**：
  - 第一页：所有课程与教师信息字段（包括合班班级列表、小组学生名单等）。
  - 第二页：每一行的 `教学内容` 与 `备注`。
  - 第三页：审核意见等文本（如需要）。

- **无需流程状态**：
  - 不引入“草稿 / 已提交 / 退回重填”等工作流状态。
  - 教师与管理员可以在权限允许范围内随时修改，系统始终保存**当前最新版本**。

- **导出行为**：
  - 导出 Word 时，后端从数据库实时读取：
    - 头信息（第一页）
    - 行信息 + 排课信息 + 禁排信息（第二页）
    - 固定审核模板（第三页）
  - 将上述数据填充进约定好的 `.docx` 模板中，并提供下载。
  - 该 `.docx` 模板直接来源于现有的《多声部音乐分析与写作2》教学日历.docx 文件，仅在其中增加必要的占位符，不对其原有版式（分页、表格结构、字体、行高、列宽等）做任何实质性调整，确保导出文件在视觉与格式上与原始文档保持一致。
  - **导出文件命名规则**：
    - 基本格式：`教师姓名 + 课程名称 + 班级`，例如：`谷浚宝_多声部音乐分析与写作2_音乐学2401.docx`。
    - 小组课：班级后追加小组序号，用连字符区分，例如同一班级的两个小组分别命名为：`音乐学2301-1`、`音乐学2301-2`，最终文件名举例：`谷浚宝_多声部音乐分析与写作2_音乐学2301-1.docx`。

### 6. 主键与数据模型设计要点（逻辑层面）

> 此处为逻辑主键设计，具体实现可按现有 ORM / 数据库风格调整命名。

#### 6.1 头信息（信息页 + 全局设置）

- 建议逻辑唯一键：
  - `(semester_id, teacher_id, course_id, teaching_class_id, group_id)`
- 存储内容：
  - 第一页所有展示字段（学院、系部、授课专业班级、教材、总学时等）
  - 小组课时的小组学生名单

#### 6.2 行信息（第二页每一行）

- 每行绑定到一个“头信息记录”，并根据是否有真实排课记录分两类：

1. **有排课的行（正常上课/补课等）**：
   - 绑定字段：
     - `calendar_header_id`（外键 → 头信息）
     - `schedule_id`（外键 → 排课记录）
   - 由此确保：
     - 若后续对该节课调课，只要更新 `schedule_id` 对应记录，导出时即可获得最新日期 / 节次 / 学时。

2. **空周行（未排课但在学期中）**：
   - 没有对应的 `schedule_id`。
   - 逻辑唯一键可为：
     - `(calendar_header_id, week_number, is_empty = true)`
   - 通过学期周次配置生成，确保每个周次在导出的日历中都有体现。

- 每行还包含：
  - `week_number`
  - `date`（可为空，仅在有课时使用）
  - `time_slot_display`（如 `3-4 节`，可为空）
  - `hours`（学时数，可为空）
  - `teaching_content`（教学内容）
  - `remark`（备注，节假日禁排原因等）

### 7. 与后续实现相关的注意点

- **排序规则**：
  - 导出与页面展示时，按 `week_number` 升序，再按 `date`（若有）与节次顺序排序。

- **合班与小组显示的一致性**：
  - 内部逻辑可继续使用教学班 id / 小组 id 来关联排课；
  - 对用户展示时，应尽量使用“实际班级名称列表 + 小组学生姓名”来增强可读性。

- **节假日禁排与空周生成的时机**：
  - 建议在前端页面加载或导出前，由后端统一根据：
    - 学期周次配置
    - 排课结果
    - 禁排/节假日配置
  - 生成完整的行列表（包含空周行），前端只负责展示与编辑“教学内容 / 备注”，不自行推演业务规则。

### 8. Word 模板导入（教师上传）

> 目标：允许教师基于已导出的教学日历 Word，在本地编辑“教学内容 / 备注”等后，再上传回系统，用于回填数据库中的行数据，方便后续再次导出与在线查看。

#### 8.1 使用入口与前端交互

- 在 `教学日历` 页面中，为当前选定的组合（学期 + 教师 + 课程 + 教学班 + 小组）提供按钮：
  - `从 Word 模板导入`
- 使用流程：
  1. 教师先在系统内生成并下载一份教学日历 Word（保证结构与系统模板一致）。
  2. 在本地 Word 中补充或修改第二页表格中的“教学内容 / 备注”等内容（不建议修改周次 / 日期 / 节次结构）。
  3. 回到系统的同一教学日历页面，点击 `从 Word 模板导入` 上传该 `.docx`。
  4. 系统解析文档，将其中的“教学内容 / 备注` 回填到对应的行记录中。

#### 8.2 模板结构与约束

- 仅支持以系统导出的教学日历 Word 为基础进行修改后再导入，确保：
  - 三页整体结构不被破坏；
  - 第二页教学日历表格仍保留表头：`周次 / 授课日期 / 节次 / 学时 / 教学内容 / 备注`；
  - 行顺序未被大规模调整（推荐保持系统原有顺序）。
- 不依赖教师在 Word 中修改日期 / 周次 / 节次等信息，这些字段仍以系统排课与配置为准。

#### 8.3 行匹配与数据回填策略

- 为降低解析复杂度，行匹配采取**顺序映射优先**的策略：
  - 系统内部先根据既有规则（第 4.2 节）生成当前教学日历对应的行列表（包括空周行），并按 `week_number + date + time_slot` 排序。
  - 解析上传的 Word 文档中第二页表格的**表体行**（跳过表头），按出现顺序生成同样数量的行列表。
  - 假定教师未随意插入/删除行、未改变整体顺序的前提下，两边按索引一一对应：
    - 对应的系统行 ← Word 中行：
      - 系统行的 `teaching_content` 更新为 Word 中“教学内容”单元格文本；
      - 系统行的 `remark` 更新为 Word 中“备注”单元格文本。
  - 若上传文档中的行数与系统行列表数量不一致：
    - 可以直接拒绝导入并给出错误提示，或进入“宽松模式”（例如只按最短长度匹配，剩余行忽略），具体策略可根据后续实现时再决定。

- 重要约束：
  - 周次 / 授课日期 / 节次 / 学时 等字段以系统内部数据为准，**不会被上传的 Word 覆盖**；
  - 导入仅用于更新文本类字段：`teaching_content` 与 `remark`。

#### 8.4 存储与审计（可选）

- 可选地，将最近一次成功导入的 Word 文件进行存储（例如路径或简单备份），用于：
  - 追溯问题；
  - 或在必要时对比差异。
- 但**导出时仍统一使用系统维护的标准模板**进行填充，不直接复用上传文件作为导出模板。

### 9. 同年级教学内容模板与班级类型

#### 9.1 年级识别

- 从班级 ID 解析年级：如「音乐学2501」→ 2025 级，「音乐学2304」→ 2023 级。

#### 9.2 班级类型区分（专业本与普通班不共用）

- **专业本（专升本）和普通班不能共用一套教学内容**。
- 年级模板按 `(学期, 课程, 年级, 班级类型)` 唯一确定。
- 班级类型：`general`（普通班）或 `upgrade`（专升本）。
- 识别规则：
  - 班级名含「专升本」→ 专升本；
  - Class 表 `student_type` 为 `upgrade` → 专升本；
  - 班号 04 结尾（如 2304、2404、2504）→ 专升本；
  - 否则 → 普通班。

#### 9.3 导入与自动填充

- 导入 Word 时，若选择了班级，教学内容同时保存为该年级该班级类型的模板。
- 同年级同班级类型的其他班级/小组加载日历时，自动使用该模板填充（按实际排课周次映射；若实际课时少于 16 次，则 16 条内容平分到实际周次）。
